# Basak (باصك) — logic and App Store readiness audit, October 2026

Scope: the Flutter app (`mobile_app/`, student and supervisor flows), the dashboard (`admin_web/`) and the
database (`supabase/`). For SQL, the **live** definitions on project `hnwpkkryxovhmsrokdsd` were read with
`pg_get_functiondef`, `pg_policies`, `pg_trigger` and `cron.job`, because migrations redefine many functions several
times. File references point to the migration that holds the current definition. Data checks were read-only
`count(*)` queries. No personal data was printed.

Every finding below was checked in code or in the live database. Claims that could not be confirmed were dropped.
Severity: **P0** blocks release, or causes data loss or a security hole · **P1** a broken core flow, a privacy
leak or a likely App Review rejection · **P2** a wrong result or a dead end with a workaround · **P3** hygiene and
polish. Effort: S is under half a day, M is 1–2 days, L is more.

"Fixed this round?" is left blank for the lead to fill in. Items the audit agent edited in this round are marked
"→ see §Edits".

**Counts: P0 = 2 · P1 = 9 · P2 = 12 · P3 = 11 (34 findings).**
